## Both cache, and they differ in how much else they do

At their core, both tools do the same job. They read your workspace, work out which packages depend on which, run tasks in the right order and skip tasks whose inputs haven't changed by restoring the result from a cache. With a remote cache, your teammates and CI share those results.

The difference is scope. **Turborepo** is a task runner and cache for JavaScript and TypeScript, and that's all. **Nx** also generates code, enforces rules about which projects may import which, works with Java, .NET and other languages, and offers distributed CI through Nx Cloud.

## Turborepo is the fastest way to faster builds

<ToolFacts tool="Turborepo" price="Free; Vercel Remote Cache free on all plans" runsOn="Node.js workspaces (npm, pnpm, Yarn, Bun)" license="Open source (MIT)" />

Add Turborepo to an existing workspace and describe your tasks in one file:

```json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"]
    },
    "test": {
      "dependsOn": ["build"]
    },
    "lint": {}
  }
}
```

`^build` means "build my dependencies first". `outputs` tells Turborepo what to cache. Then run `npx turbo run build test lint`. The second time, unchanged packages come straight from the cache.

For a shared cache, run `npx turbo login` and `npx turbo link`. Vercel Remote Cache is free on all Vercel plans, even if you don't host your apps there, subject to fair use. You can also point Turborepo at a self-hosted cache.

## Nx is a full platform for big repos

<ToolFacts tool="Nx" price="Free; Nx Cloud from $0 (Hobby)" runsOn="Node.js, plus Gradle, Maven and .NET via plugins" license="Open source (MIT)" />

Run `npx nx@latest init` in an existing repo and Nx infers tasks from your tools' config files. From there it adds what Turborepo leaves out. Generators scaffold new apps and libraries the same way every time. Module boundary rules stop one team's code from importing another's. And `nx affected` runs tasks only for the projects a change touches:

```sh
npx nx affected -t lint test build
```

Nx supports JavaScript and TypeScript, Java with Gradle or Maven, and .NET as first-party plugins. Community plugins cover Python, Rust, Go and PHP.

Nx Cloud's free Hobby plan includes 50,000 credits a month, 5 contributors and remote caching. Team costs $19 per contributor per month and adds usage-based billing past the included credits. There's more to learn than with Turborepo: generators, project configuration and Nx's CLI.

## How to choose in 30 seconds

- **A JS/TS monorepo, faster builds today:** Turborepo.
- **Java, .NET or mixed languages in one repo:** Nx.
- **Many teams, strict rules about who imports what:** Nx.
- **A free shared cache with no credit limits:** Turborepo with Vercel Remote Cache.

## FAQ

### Do I need Vercel to use Turborepo?

No. Turborepo runs locally and in any CI. Vercel Remote Cache is optional, and free on every Vercel plan even if you don't deploy there. You can also use a self-hosted cache.

### Can Nx handle non-JavaScript projects?

Yes. Nx has first-party plugins for Java (Gradle and Maven) and .NET, and community plugins for Python, Rust, Go and PHP.

### Which one is easier to learn?

Turborepo. You need one config file and a handful of task options. Nx has more concepts, like generators, inferred tasks and project boundaries, because it does more.
