## Nest runs on top of Express

This comparison gets framed as a rivalry, but it isn't one. Express is a minimal HTTP framework: routing, middleware, request and response. NestJS is an application framework that uses Express underneath by default. Since NestJS 11 it uses Express 5. You can switch it to Fastify with one adapter.

So the real question is whether you want Nest's structure on top: modules, controllers, providers, dependency injection and decorators, all in TypeScript.

## The same endpoint in both

A `POST /books` that creates a book. In Express 5:

```js
import express from 'express';
import { createBook } from './books.js';

const app = express();
app.use(express.json());

app.post('/books', async (req, res) => {
  const book = await createBook(req.body);
  res.status(201).json(book);
});

app.listen(3000);
```

If `createBook` throws, Express 5 sends the error to your error-handling middleware on its own. In Express 4 you had to catch it and call `next(err)`, and forgetting to do that was a classic bug.

In NestJS you write a controller, and the service is injected:

```ts
import { Body, Controller, Post } from '@nestjs/common';
import { BooksService } from './books.service';
import { CreateBookDto } from './dto/create-book.dto';

@Controller('books')
export class BooksController {
  constructor(private readonly booksService: BooksService) {}

  @Post()
  create(@Body() dto: CreateBookDto) {
    return this.booksService.create(dto);
  }
}
```

There's more code, plus a module that registers both classes. In return, every endpoint in the codebase follows this pattern, POST returns 201 by default, and you can test the controller by passing a fake `BooksService`.

## Express is small and everyone knows it

<ToolFacts tool="Express" price="Free" runsOn="Node.js" license="Open source (MIT)" />

Express 5.1 became the default on npm in March 2025, with an official support schedule. Version 5 handles rejected promises in async handlers, so you can drop the try/catch boilerplate. It also updated path matching, which can break some route patterns when you upgrade from v4.

Express doesn't decide your folder structure, validation library or how services talk to each other. That's freeing in a small service. In a big codebase, someone has to write those rules down and enforce them in reviews.

## NestJS gives a large team one structure

<ToolFacts tool="NestJS" price="Free" runsOn="Node.js (Express or Fastify)" license="Open source (MIT)" />

Nest organizes code into modules. Each one has controllers for HTTP and providers for logic, connected by dependency injection. Guards, pipes and interceptors handle auth, validation and logging in the same place every time. A new developer who knows Nest can find their way in a Nest project they've never seen.

NestJS 12 came out in August 2026. Its core packages now ship as ESM, and route decorators like `@Body()` accept Standard Schema validators. It needs Node.js 20.19+ or 22.12+.

The cost is the learning curve: decorators, modules, providers and how injection scopes work. For a three-endpoint service, that's more framework than code.

## How to choose in 30 seconds

- **A small service or prototype:** Express.
- **A large codebase shared by many developers:** NestJS.
- **You want Nest's structure with a faster HTTP layer:** NestJS with the Fastify adapter.
- **You're still on Express 4:** upgrade to Express 5 before you decide anything else.

## FAQ

### Does NestJS replace Express?

No. NestJS uses Express 5 as its default HTTP layer and adds structure on top. You can use Fastify instead with `@nestjs/platform-fastify`.

### Do both work with TypeScript?

Yes. NestJS uses TypeScript by default. Express works with TypeScript too, but you set up the compiler and install the type definitions yourself.

### Is Express still maintained?

Yes. Express 5.1 is the default version on npm, and the project publishes a support schedule for the v4 and v5 lines.
