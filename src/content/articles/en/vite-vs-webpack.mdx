## The difference starts in development

**Webpack** builds a bundle before it serves your app, even in development. It walks your whole dependency graph, runs loaders and writes the bundle into memory. The bigger the app, the more work happens before the first page loads.

**Vite** doesn't bundle your source code in development. It serves files as native ES modules and lets the browser request what it needs. When you edit a file, only that module is replaced. Vite's docs say this keeps startup and updates fast as an app grows. That's their claim; we haven't benchmarked it.

For production, Vite does bundle. Since Vite 8, released in March 2026, one Rust-based bundler, Rolldown, handles that. It replaced the old split of esbuild for some tasks and Rollup for the build.

## The config, side by side

A React app with TypeScript in Vite:

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
});
```

TypeScript, CSS, the HTML entry and the dev server work with no extra setup. The classic webpack setup for the same app spells out each file type:

```js
// webpack.config.js
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  entry: './src/index.tsx',
  output: { filename: '[name].[contenthash].js', clean: true },
  resolve: { extensions: ['.tsx', '.ts', '.js'] },
  module: {
    rules: [
      { test: /\.tsx?$/, use: 'ts-loader', exclude: /node_modules/ },
      { test: /\.css$/, use: ['style-loader', 'css-loader'] },
    ],
  },
  plugins: [new HtmlWebpackPlugin({ template: './index.html' })],
};
```

Webpack is closing that gap. Since 5.109, built-in CSS, HTML, TypeScript and async WebAssembly support are on by default when no loader is registered for them. That can remove several of those rules.

## Vite is the default for new apps

<ToolFacts tool="Vite" price="Free" runsOn="Node.js" license="Open source (MIT)" />

Vite is the default build tool for many frameworks, including Vue, SvelteKit, Astro and React Router. You get a fast dev server, hot module replacement and sensible production defaults with almost no config.

Vite 8 moved production builds to Rolldown and kept compatibility with existing Vite plugins. Vite's own announcement cites builds up to 10 to 30 times faster. That number is theirs. Vite 8.1 followed in June 2026.

## Webpack still wins on control and federation

<ToolFacts tool="Webpack" price="Free" runsOn="Node.js" license="Open source (MIT)" />

Webpack is far from abandoned. It shipped regular releases through 2026, up to 5.111 in September, with stable ES module output, native CSS and HTML handling and a published roadmap toward webpack 6. Its loader and plugin system gives you control over every step of the build, which large apps with unusual needs still rely on.

Module Federation is its biggest reason to stay. Separately built apps load each other's code at runtime, which is the basis of many micro-frontend setups. The newer Module Federation 2.0 features run on webpack and Rspack, a webpack-compatible bundler written in Rust.

## How I set up Vite on React projects

All my recent React projects use Vite, and two settings cover most of what I need beyond the defaults. First, a dev proxy, so the frontend can call the API on the same origin and you skip CORS problems in development:

```ts
export default defineConfig({
  plugins: [react()],
  server: {
    proxy: {
      '/api': 'http://localhost:3000',
    },
  },
});
```

Second, environment variables. Only variables that start with `VITE_` reach browser code, through `import.meta.env.VITE_API_URL`. That prefix is a safety net: keep secrets without it, and they never ship to the browser.

I still maintain webpack configs on older projects. My rule is simple: if the build works and nobody touches the config, leave it. If the dev server is slowing the team down every day, plan the move to Vite.

## How to choose in 30 seconds

- **A new app:** Vite.
- **Micro-frontends with Module Federation:** webpack, or Rspack if you want webpack compatibility in Rust.
- **A large webpack build that works:** keep it, and upgrade to the latest 5.x.
- **Slow webpack dev server and no federation:** migrate to Vite.

## FAQ

### Does Vite bundle code for production?

Yes. Vite serves unbundled modules in development and bundles for production. Since Vite 8 that bundler is Rolldown.

### Is Vite faster than webpack?

Vite's docs and its Vite 8 announcement say so, especially for dev server startup and updates. We haven't benchmarked them, so treat those numbers as the projects' own claims.

### Can I use webpack plugins in Vite?

No. Webpack plugins and loaders don't run in Vite. Vite has its own plugin system, compatible with many Rollup-style plugins, and equivalents exist for most common loaders.
