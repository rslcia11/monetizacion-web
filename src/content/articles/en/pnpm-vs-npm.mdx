## Copy versus link

The core difference is how `node_modules` gets filled. **npm** copies every package into each project and flattens the tree, so ten projects that use the same React version keep ten copies. **pnpm** keeps one copy of every file in a global content-addressable store and hard-links it into each project. A hundred projects on the same version cost one copy on disk.

That layout has a second effect. In a flat `node_modules`, your code can import a package you never listed in `package.json`, because it happened to be hoisted there by something else. pnpm's symlinked layout only exposes your declared dependencies to your code, which catches those "phantom dependency" bugs early.

## pnpm stores each package once

<ToolFacts tool="pnpm" price="Free" runsOn="Windows, macOS, Linux" license="Open source (MIT)" />

pnpm 12 is a rewrite in Rust and the current release line. In pnpm's own published benchmark for a project with many packages, a clean install took 14.3 seconds with pnpm 12 and 1 minute 51 seconds with npm. Those are pnpm's numbers, measured on pnpm's setup. Your project will differ, but the direction is consistent across their scenarios.

Workspaces are where pnpm shines. A `pnpm-workspace.yaml` lists your packages, and `workspace:` versions link them locally. Strictness has an escape hatch: if an old package relies on phantom dependencies, the hoisting settings can expose just that package.

Install pnpm from its website or with a standalone script. Corepack is no longer bundled with Node.js 25 and later, so don't rely on it to provide pnpm.

## npm is already installed

<ToolFacts tool="npm" price="Free" runsOn="Windows, macOS, Linux" license="Open source (Artistic 2.0)" />

npm comes with Node.js, so every CI image, hosting platform and tutorial supports it. Nothing to install or explain to a new teammate.

npm 12, released in July 2026, closed one of pnpm's old advantages. Lifecycle scripts from dependencies are now blocked unless your project allows them, and git and tarball-URL dependencies are off by default. It also removed `npm shrinkwrap` and turned unknown config keys into errors, so check your `.npmrc` before upgrading.

Its layout hasn't changed: packages are still copied per project in a flat tree, which uses more disk and lets code import packages it never declared.

## How to switch from npm to pnpm

pnpm can build its lockfile from your existing `package-lock.json`, so you keep the same resolved versions:

```sh
pnpm import
rm -rf node_modules package-lock.json
pnpm install
```

Run your tests. If something fails with "Cannot find module", your code was relying on a phantom dependency: add that package to your dependencies. Finally, pin the pnpm version for your team in `package.json`:

```json
{
  "packageManager": "pnpm@12.8.0"
}
```

## How to choose in 30 seconds

- **A monorepo:** pnpm.
- **Many projects on one laptop, or slow CI:** pnpm.
- **Zero setup, maximum compatibility:** npm.
- **A legacy project with fragile tooling:** npm.

## FAQ

### Is pnpm actually faster than npm?

In pnpm's published benchmarks, yes, in every scenario they test. A clean install of their "alotta-packages" project took 14.3 seconds with pnpm 12 and 1 minute 51 seconds with npm. Those are pnpm's measurements, not ours.

### How does pnpm save disk space?

It keeps one copy of each file in a global store on your machine and hard-links it into each project's `node_modules`, instead of copying packages into every project.

### Do I still need Corepack for pnpm?

No. Corepack isn't bundled with Node.js 25 and later. Install pnpm with the methods on pnpm's installation page, and pin the version with the `packageManager` field.
